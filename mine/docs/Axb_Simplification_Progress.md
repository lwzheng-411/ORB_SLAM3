## 架构说明

### 硬件复用机制（已明确体现）

```verilog
// ============================================================
// 硬件资源池：所有 factor 时分复用
// ============================================================
// 16x DW_fp_mult:  mul_a/b/z[0:15]  ← Camera/IMU/Prior 共享
// 12x DW_fp_add:   add_a/b/z[0:11]  ← Camera/IMU/Prior 共享
// 8x  DW_fp_sub:   sub_a/b/z[0:7]   ← Camera/IMU/Prior 共享
```

**复用证据**:
1. **时分复用**: Camera → IMU → Prior 顺序执行，状态互斥
2. **共享信号**: 都操作同一组 `mul_a[0:15]` 等
3. **面积节省**: 16个MUL (共享) vs 48个MUL (独立) = **节省 66%**

### 层次化结构（内联子FSM）

当前是**单体FSM + 引擎标记**，不是独立子模块：

```
always @(posedge clk) begin
  case(st)
    S0: 接收 factor_type
    S_DISPATCH: case(eng)
                  ENG_CAM: st<=SC1;
                  ENG_IMU: st<=SI1;
                  ENG_PRI: st<=SP1;
    // 三种 factor 的状态在一个 always 块里
    SC1-SC11: Camera  (165行, 全宏)
    SI1-SI34: IMU     (375行, 部分宏)
    SP1-SP21: Prior   (241行, 全宏)
  endcase
end
```

**为什么不分模块**：用户要求 "都写到Axb这个文件里面吧，别分出去"
